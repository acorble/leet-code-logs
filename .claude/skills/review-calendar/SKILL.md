# 解き直しの予定をカレンダーに登録する

予定の中身（日時・タイトル・説明・通知）は `scripts/review_events.py` が作る。
**自分で組み立てず、スクリプトの出力をそのまま使うこと。** 形式をそろえるための仕組み。

## 守ること

- 登録先は**メインカレンダーだけ**。`calendarId` は指定しない（省略 = primary）。
  研究室カレンダー (nanosat.nuae@gmail.com) やその他のカレンダーは読みも書きもしない。
  このリポジトリでは `.claude/hooks/calendar-guard.sh` が強制している。
- 登録するのは予定の作成だけ。既存の予定の変更・削除は、ユーザーに頼まれたときだけ。

## 1. 予定の候補を出す

```bash
./.venv/bin/python scripts/review_events.py            # 今日から 7 日以内
```

- ユーザーが期間を言ったら `--days N` で合わせる（「2 週間分」→ `--days 14`）
- 出力の `events` が登録候補、`overdue` は期限切れで日付が決まっていない問題

## 2. 期限切れの問題をどうするか

`overdue` が空でなく、ユーザーが期限切れについて何も言っていなければ、
登録の前に**一度だけ**まとめて聞く。例:

> 期限切れが 29 問あります。今週やる上位 5 問（543, 125, ...）も入れますか？
> 入れるなら、10/23 から 1 日 1 問ずつ割り振ります。

- 日付は、`events` の予定がない日を優先して 1 日 1 問で割り振る。順番は `overdue` の並び（遅れが大きい順）
- 決まったら `--assign 番号=YYYY-MM-DD` を付けて再実行し、その出力を使う
- 「期限切れはいらない」「今後の予定だけ」と言われたら聞かずに進める

## 3. 二重登録を防ぐ

登録したい期間の予定を、メインカレンダーで確認する:

- `list_events` に `fullText: "LeetCode 解き直し"`、`startTime` / `endTime` に対象期間を指定する
- `summary` が同じ予定がすでにある問題は登録しない（日付が違っても、同じ問題が期間内にあれば飛ばして報告する）

## 4. 登録する

`events` の 1 件ごとに `create_event` を呼ぶ。渡すのは次の 5 つだけで、値はスクリプトの出力そのまま:

- `summary` / `startTime` / `endTime` / `description` / `overrideReminders`

`calendarId`・`timeZone`・`attendees` は付けない。独立した呼び出しなので並列でよい。

## 5. 報告する

表で返す: 日時 / 問題 / 通知（前日 23:00・当日 7:00）/ 予定へのリンク (`htmlLink`)。
二重登録で飛ばしたもの、期限切れで入れなかったものがあれば一言添える。
