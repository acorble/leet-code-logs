## 問題の要約

高さバランス木か（すべてのノードで左右の部分木の高さの差が 1 以下か）を判定する。

## 計算量

- 時間: O(n) — 各ノードを 1 回ずつ訪れ、深さを 1 回だけ計算する
- 空間: O(h) — 再帰スタック。木が偏ると最悪 O(n)

素朴に書くと「各ノードで左右の高さを測り直す」形になり O(n log n)〜O(n^2) になる。
下から深さを持ち上げることで、測り直しを避けている。

## 学び・再利用できるパターン

- **深さを下から持ち上げる後順走査**。「高さ」と「判定結果」を同時に返すのが要点。
  各ノードで高さを測り直すと同じ計算を何度も繰り返すことになる。
  [543. Diameter of Binary Tree](../0543-diameter-of-binary-tree) も同じ形
  （深さを持ち上げつつ、途中で答えを更新する）。
  ただし 543 を解いた 7/28 時点ではまだ「各ノードで測り直す」形で書いていた
- **部分木の答えを親に返すか、外側の変数に溜めるか**の 2 通りがある。
  ここでは `self.isBalancedTotally` に溜める形を採った。
  返り値だけで完結させることもできる（下記）
- `[3,9,20,null,null,15,7]` のように根では釣り合っていても、深い位置で崩れることがある。
  「根だけ見て判定しない」——すべてのノードで条件を満たす必要がある

### 返り値の bool が使われていない

`maxDepthAndIsBalanced` はタプルの 2 番目に bool を返しているが、
呼び出し側 (`isBalancedLeft` / `isBalancedRight` / `isBalanced`) はどれも
**その値を一度も読んでいない**。答えは `self.isBalancedTotally` だけで決まっている。

つまり返り値は深さだけで足りる。逆に、外側の変数を使わずに
「深さと判定結果のタプル」だけで書き切ることもできる。どちらか一方に寄せると短くなる。
