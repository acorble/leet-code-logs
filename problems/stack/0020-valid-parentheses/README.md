## 問題の要約

`()[]{}` の 6 種類の文字だけからなる文字列が、正しく閉じた括弧の並びになっているかを判定する。
閉じ括弧は同じ種類で、しかも**いちばん最後に開いた括弧**と対応していなければならない。

## 学び・再利用できるパターン

### 「いちばん最後に開いたもの」と対応させるなら Stack

`([)]` が不正になるのは、`)` が来たとき、いちばん最後に開いたのが `[` だから。
閉じ括弧が対応すべき相手は、常に**直前に開いて、まだ閉じていない括弧**になる。
「最後に入れたものから取り出す」ので Stack がそのまま合う。

```
s:      (     [     ]     )
stack: [(]  [( []  [(]   []    → 空になったので True
```

[150](../0150-evaluate-reverse-polish-notation)（演算子が来たら直前に積んだ 2 つの数を使う）、
[739](../0739-daily-temperatures)（新しい日が来たら直前に待っていた日から確認する）と同じ形。

### 不正になるのは 3 パターン

テストもこの 3 つを押さえている。

| パターン | 例 | どこで分かるか |
| --- | --- | --- |
| 種類が合わない | `(]`、`([)]` | 閉じ括弧と Stack の先頭が対応しない |
| 閉じる相手がいない | `]` | 閉じ括弧が来たとき Stack が空 |
| 閉じられずに残る | `((` | 最後まで読んで Stack が空でない |

3 つ目を忘れて最後に `return True` だけにするのが典型的なバグ。
1 回目の解答は最後に `if not stack` を見ていて、3 つとも正しく扱えている。

### 対応表を dict にすると分岐が 1 つになる

```python
pairs = {")": "(", "]": "[", "}": "{"}
for c in s:
    if c in pairs:  # 閉じ括弧
        if not stack or stack.pop() != pairs[c]:
            return False
    else:           # 開き括弧
        stack.append(c)
return not stack
```

- 括弧の種類が増えても、`pairs` に 1 行足すだけで済む
- `if not stack or ...` は、Stack が空なら右側（`stack.pop()`）を実行しない（短絡評価）。
  空の Stack から pop してエラーになるのを、この 1 行で防いでいる
- 最後の `return not stack` は `if not stack: return True else: return False` と同じ

### 細かい点（1 回目）

- `a = stack[-1]` を読めた時点で Stack は空でないので、そのあとの `if stack:` は 3 つとも要らない
- 先頭を `stack[-1]` で見て、対応していたら `pop()` する 2 段階になっている。
  対応しなければどうせ `return False` するので、最初から `pop()` して比べても結果は同じ
- `if c == '(' or c == '{' or c == '['` は `if c in '({['` と書ける

### 2 回目: `pop()` を条件の中に入れたら、空の Stack で落ちた

2 回目は「先頭を見てから pop」の 2 段階をやめて、条件の中で直接 `pop()` している。
1 回目の「最初から `pop()` して比べても結果は同じ」を実際にやった形で、コードは短くなった。

```python
if c == ')' and stack.pop() == '(':
```

ただ、1 回目にあった **Stack が空かどうかの確認**も一緒に消えてしまった。
`]` のように、開き括弧がないまま閉じ括弧が来ると、空の Stack から `pop()` して
`IndexError: pop from empty list` になる（`test_close_without_open` が落ちるのはこれ）。
上の表の「閉じる相手がいない」パターン。

| | 1 回目 | 2 回目 |
| --- | --- | --- |
| 先頭の取り出し | `stack[-1]` で見てから `pop()` | 条件の中で直接 `pop()` |
| 空の Stack の確認 | `if stack:` あり | **なし → エラー** |
| 結果 | AC | RE |

直し方は、`pop()` する前に空なら `False` を返すだけ。

```python
else:
    if not stack:
        return False
    if c == ')' and stack.pop() == '(':
        ...
```

上の dict 版の `if not stack or stack.pop() != pairs[c]` も同じことを 1 行でやっている。
**`pop()` や `[-1]` を書いたら、空のときにどうなるかを必ず考える**のが Stack 問題の決まりごと。

`and` の短絡評価のおかげで、`c == ')'` が偽なら `stack.pop()` は実行されない。
そのため、1 つの閉じ括弧で `pop()` が 2 回呼ばれることはなく、空でないときの判定は正しい。
