## 問題の要約

文字を k 個まで別の文字に置き換えてよいとき、
**すべて同じ文字にできる連続した部分文字列**の最大の長さを返す。

## 計算量

- 時間: O(n × 文字種) 相当。加えて毎回 `s[left:right+1]` を作るぶん定数倍が重い
  （実測で約 1.3〜1.8 倍）
- 空間: O(文字種) — 窓の中の頻度を dict で持つ

## 学び・再利用できるパターン

- **窓の状態を「頻度の dict」で持つ**スライディングウィンドウ。
  [3](../0003-longest-substring-without-repeating-characters) は
  「あるか無いか」だけでよかったので set だったが、
  こちらは**何個あるか**が要るので dict になる。**必要な情報の粒度で入れ物を選ぶ**
- 窓が成立する条件は **`窓の長さ - 最頻の出現数 <= k`**。
  「最頻の文字はそのままにして、残りを全部置き換える」のが常に最善なので、
  置き換える個数 = 窓の長さ − 最頻の出現数
- 条件が壊れたら左を詰める、という骨格は 3 と同じ。
  **条件式だけを差し替えれば別の問題になる**のがこの型の強み

### 長さを取るのにスライスは要らない（検証済み）

```python
while k < len(s[left:right + 1]) - maxFrequency:    # 部分文字列を作ってから長さを取る
while k < (right - left + 1) - maxFrequency:        # 引き算で足りる
```

`len(s[left:right+1])` は**長さを知るためだけに文字列をコピー**している。
`right - left + 1` で同じ値が得られる。

- 等価性: 12,000 パターンで確認（不一致なし）
- 速度: 長さ 40,000 で **約 1.8 倍**の差

しかも同じファイルの最後の行では、既に `res = max(res, right - left + 1)` と
**引き算で長さを求めている**。同じ量を 2 通りの方法で計算している状態。

前日の [3](../0003-longest-substring-without-repeating-characters) でも
`s[left:right].index(...)` という不要なスライスがあった。
**「文字列を切り出す前に、添字の計算で済まないか」を疑う**。

### もう一歩の改善

`maxFrequency = max(map.values())` を毎回計算しているが、
**窓を縮めたときに最頻値を減らす必要はない**（答えが小さくなる方向には
窓を広げないので、過去の最大値を持ち回っても結果は変わらない）。
`maxFrequency` を 1 変数で持ち回れば `max()` の走査が消えて O(n) になる。
