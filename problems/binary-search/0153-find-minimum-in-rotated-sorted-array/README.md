## 問題の要約

昇順の配列をどこかで回転させたもの（例: `[3,4,5,1,2]`）から、最小値を返す。
O(log n) で解く必要がある。値に重複は無い。

## 計算量

- 時間: O(log n)
- 空間: O(1)

## 学び・再利用できるパターン

- **回転した配列では「末尾の値」が基準になる**。回転後の配列は
  「大きい塊 → 小さい塊」の 2 段構えで、末尾は必ず小さいほうの塊にいる。
  だから `nums[m] <= nums[-1]` なら m は**小さいほうの塊**にいると分かり、
  最小値は m かそれより左にある
- 探しているのは「小さいほうの塊の先頭」。
  = **条件を満たす最も左の位置**を探す形で、
  [875. Koko](../0875-koko-eating-bananas) の「条件を満たす最小の k」と同じ狙い。
  875 は `right = m` で候補を残したが、こちらは `minimum` に控えてから `r = m - 1` している。
  どちらも「候補を保持しながら左へ詰める」型
- 値の大小ではなく**「どちらの塊にいるか」で分岐する**のが、回転配列の問題の共通点。
  33. Search in Rotated Sorted Array も同じ考え方

### 冒頭の早期 return は無くても正しい

```python
if nums[0] < nums[len(nums) - 1]:
    return nums[0]
```

回転していない場合を先に弾いているが、**この分岐を外しても答えは変わらない**
（長さ 1〜39 の全配列 × 全回転量 780 パターンで検証済み）。
回転していない配列では `nums[m] <= nums[-1]` が常に真になり、
`r` が縮み続けて最終的に `minimum` が `nums[0]` に落ち着くため。

- 残す意味: 回転していないと分かれば O(1) で返せる（速度の最適化）
- 外す意味: 分岐が 1 つ減り、`else` のインデントも消えて短くなる

どちらでもよいが、**「特殊ケースに見えたものが、実は一般ケースに含まれていた」**
という構図は繰り返し出てくる
（[206](../../linked-list/0206-reverse-linked-list) の `prev = None`、
[21](../../linked-list/0021-merge-two-sorted-lists) のダミーノードと同じ）。

### 細かい点

`nums[len(nums) - 1]` は `nums[-1]` と書ける。ループ内で 2 回評価しているので、
先に `last = nums[-1]` と控えておくと読みやすい。
