## 問題の要約

木を左右反転する。すべてのノードで左右の子を入れ替え、反転後の根を返す。

## 計算量

| 回 | 時間 | 空間 | |
| --- | --- | --- | --- |
| 1 | O(n) | O(h) | 再帰スタック。木が偏ると最悪 O(n) |
| 2 | O(n) | O(w) | queue。w = 最大幅。最悪 O(n) |

どちらも各ノードを 1 回ずつ訪れる。違うのは「何に積むか」だけで、
再帰は暗黙のコールスタック、BFS は自前の queue に積んでいる。
偏った木では再帰が不利（深さぶん積む）、幅の広い木では BFS が不利（幅ぶん積む）。

## 学び・再利用できるパターン

- **木を「作り変える」再帰**。これまでの問題は値を集めて返す（読み取り）だったが、
  これは木そのものを書き換える。返り値が `int` や `bool` ではなく
  **ノード**である点が違い
- 先に左右を再帰してから、戻ってきた結果を入れ替える。
  子を入れ替えてから再帰しても答えは同じになる（左右対称なので順序を問わない）
- 一時変数 `tmpleft` / `tmpright` に受けてから代入している。
  Python なら `root.left, root.right = root.right, root.left` と 1 行で書ける
  （2 回目ではこの形にしている）

### 2 回目で変わったこと

- **再帰 → BFS（反復）**。木を降りる手段が変わっただけで、やっていることは同じ。
  「各ノードで左右を入れ替える」以外に条件がないので、
  訪れる順番は何でもよい（前順・後順・レベル順、どれでも正しい）
- そのため、この問題は**再帰と反復を書き比べる練習にちょうどよい**。
  順序に意味がある問題（102 のレベル順など）ではこう入れ替えられない
- 一時変数を使わず `node.left, node.right = node.right, node.left` の 1 行に。
  Python のタプル代入は右辺を先に評価するので、入れ替えがそのまま書ける
- `deque` を使うのは 7/21 の時点で既にできていた
  （[102](../0102-binary-tree-level-order-traversal) の 1 回目 8/30 では
  `list.pop(0)` で書いていて、2 回目に deque へ戻している）
