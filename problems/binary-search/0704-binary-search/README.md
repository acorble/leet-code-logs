O(log n) で解くことが求められている（全探索は不可）。

## 計算量

- 空間: O(1)

1 回目と 2 回目でロジックは同一。差はデバッグ用 print の有無と `int(x/2)` / `x // 2` だけ。

## 学び・再利用できるパターン

- **範囲を半分に切り続ける**。`left` / `right` で候補の範囲を持ち、
  中央と比べてどちら側に絞るかを決める
- 正しく動く（長さ 1〜40 の全配列で全要素と外れ値を総当たり検証済み）。
  ただし境界の作りが標準形と違うので、下記を押さえておくと迷わない

### 標準形との違い

この解答は **範囲を 2 要素残して抜け、最後に両端を個別に確認**する形。

```python
while 1 < right - left:      # 3 要素以上ある間だけ回る
    ...
    right = middle           # middle を含めたまま狭める
# 抜けたあと left と right を個別に確認
```

標準形は **範囲が空になるまで回し、抜けたら -1** を返す。

```python
left, right = 0, len(nums) - 1
while left <= right:
    mid = (left + right) // 2      # 毎回その場で計算する
    if nums[mid] == target:
        return mid
    if nums[mid] < target:
        left = mid + 1             # mid は候補から外す
    else:
        right = mid - 1
return -1                          # 後始末が要らない
```

| | この解答 | 標準形 |
| --- | --- | --- |
| ループ終了 | 2 要素残す | 範囲が空になるまで |
| `middle` | 変数に持ち、2 箇所で更新 | ループ先頭で毎回計算 |
| 範囲の狭め方 | `right = middle`（mid を残す） | `right = mid - 1`（mid を外す） |
| ループ後 | 両端を個別に確認 | 不要（`return -1` のみ） |

- **mid を候補から外す（`mid ± 1`）と、範囲が必ず縮む**ので無限ループの心配が消え、
  ループ後の後始末も要らなくなる。この解答が末尾で 2 要素を確認しているのは、
  `right = middle` で mid を残しているぶんの帳尻合わせ
- `middle` を変数に持つと**更新箇所が 2 つに増える**（片方だけ直すとバグる）。
  ループ先頭で 1 回計算するほうが safe

### 細かい点

- `int((right - left) / 2)` より `(right - left) // 2` のほうがよい。
  結果は同じだが、`/` は一度 float にするため、非常に大きな添字では誤差が出る
  → **2 回目で `//` に修正済み**
- 1 回目にはデバッグ用の `print` が 3 箇所生きていた（`attempts/2026-06-24.py`）。
  2 回目で削除。値を追いながら組み立てた跡なので、記録として残してある

なお `middle = int(len(nums) / 2)` の初期化だけは 2 回目でも `int()` のまま。
ここも `//` に揃えると一貫する。
