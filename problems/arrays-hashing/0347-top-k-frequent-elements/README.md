## 問題の要約

整数の配列 `nums` の中で、**出現回数が多い順に k 種類**の値を返す。順番は問わない。
follow-up は「O(n log n) より速く解けるか」。

## 計算量

n は配列の長さ、m は値の種類数（m ≤ n）。

- 時間: **O(n + m log m)** — 数えるのが O(n)、種類ごとの Entry を並べ替えるのが O(m log m)。
  すべて違う値なら m = n なので O(n log n)
- 空間: **O(m)** — HashMap と Entry のリスト

## 学び・再利用できるパターン

### 「数える → 多い順に並べる」の 2 段階

1 段目の「HashMap で出現回数を数える」は [242](../0242-valid-anagram)、[49](../0049-group-anagrams) と同じ。
この問題で新しいのは 2 段目の「回数の多いものから k 個取り出す」ところで、取り出し方が 3 通りある。

| 方法 | 時間 | 考え方 |
| --- | --- | --- |
| 全部並べ替える（今回） | O(n log n) | 回数の多い順にソートして先頭 k 個 |
| ヒープ（優先度付きキュー） | O(n log k) | 大きさ k のヒープに、回数の少ないものから捨てながら入れていく |
| バケツ | **O(n)** | 回数を**添え字**にした配列に値を入れ、後ろ（回数の多い側）から k 個取る |

follow-up の「O(n log n) より速く」は、ヒープかバケツで満たせる。

### バケツ: 回数は 1〜n にしかならない

出現回数は、最小 1、最大でも配列の長さ n。だから、長さ n + 1 の配列を用意して、
`buckets[回数]` にその回数の値を入れていけば、並べ替えなくても回数順に並ぶ。

```
nums = [1,1,1,2,2,3]   →   回数: {1: 3, 2: 2, 3: 1}

buckets[1] = [3]
buckets[2] = [2]
buckets[3] = [1]        ← 後ろから見ていき、k 個集まったら終わり
```

「値が取りうる範囲が小さいなら、並べ替える代わりにその値を添え字にする」は、
並べ替えを O(n) にするときの定番の考え方。

### 細かい点（Java）

- `new ArrayList(set)` は型引数が抜けているので、コンパイル時に警告（unchecked）が出る。
  `new ArrayList<>(set)` と `<>` を付けるとよい
- `Map.Entry.comparingByValue(Comparator.reverseOrder())` で「値（回数）の大きい順」に並べている。
  Java の Entry の並べ替えとしては定番の書き方
