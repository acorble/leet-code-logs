## 計算量

n は文字列の数、k は文字列の最大の長さ、g はグループの数。

- 時間: **O(n·k + n·g)** — 文字数を数えるのが n·k。各文字列について、既にあるグループを先頭から 1 つずつ比べるのが n·g
  （Map の比較 1 回は、最大 26 種類のキーを見るだけ）。
  すべてが別のグループになると g = n なので **O(n²)**。
  n = 10⁴、k = 100 の最悪ケースで、手元では約 1.3 秒かかった
- 空間: **O(n)** — 文字列ごとの Map（それぞれ最大 26 キー）と、インデックスのリスト

## 学び・再利用できるパターン

### 「同じグループか」を比べて回る代わりに、グループの名前（キー）を作る

この解答の遅いところは、新しい文字列が来るたびに、**既にあるグループを先頭から 1 つずつ比べている**こと
（コードのコメントにある「n-1 回の判定が必要」の部分）。

アナグラム同士は、ある 1 つの値が必ず一致する。その値を dict のキーにすれば、比べて回らずに **1 回で**グループが決まる。

| キーにするもの | 例（`"eat"`） | キーを作る時間 |
| --- | --- | --- |
| 並べ替えた文字列 | `"aet"` | O(k log k) |
| 26 文字分の個数 | `(1,0,0,0,1,0,…,1,…)` | O(k) |

```python
from collections import defaultdict

groups = defaultdict(list)
for s in strs:
    groups["".join(sorted(s))].append(s)  # 「aet」というグループに入れる
return list(groups.values())
```

全体で O(n·k log k)（個数をキーにすれば O(n·k)）になり、n² の部分が消える。

[242](../0242-valid-anagram) で学んだ「並べ替えて比べる」「数えて比べる」の 2 つが、そのままキーの作り方の 2 つになっている。
コメントにある「できたら hashmap じゃなくて int[] でもやってみたい」は、2 つ目のキーにそのままつながる
（Python では list は dict のキーにできないので、`tuple(count)` に変える）。

### HashMap を「比べる」から「キーにする」へ

この解答でも、Map 同士を `.equals()` で比べる部分は正しくできている。
Java の `HashMap` は中身が同じなら `hashCode()` も同じになるので、実は**Map そのものを別の Map のキーにする**こともできる
（`Map<Map<String, Integer>, List<String>>`）。そうすると、今の考え方のまま比べて回る部分だけが消える。

### 細かい点（Java）

- `""` を `split("")` すると `[""]`（空文字 1 つの配列）になるので、空文字同士は `{"": 1}` の Map で同じグループに入る。
  結果は正しい
- 1 個目だけ特別扱いしている `if (ansIndex.size() == 0)` は無くても動く。
  空のリストに対しては内側の `for` が 1 回も回らず、`isHit` が `false` のまま新しいグループを作るので
- インデックスを集めてから最後に文字列へ戻す 2 段階にしているが、最初から文字列のリストに入れていけば 1 段で済む
