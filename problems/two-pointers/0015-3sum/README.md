## 問題の要約

整数の配列から、**足して 0 になる 3 つ組**をすべて返す。同じ組（値の組み合わせが同じもの）は 1 回だけ。
組の順番も、組の中の順番も問わない。

## 計算量

1 回目（並べ替え + 2 ポインタ）:

- 時間: **O(n²)** — 並べ替えが O(n log n)。1 つ目を固定するのが n 通りで、そのたびに 2 ポインタが O(n)
- 空間: **O(1)**（答えの配列を除く。Python の `sort()` は内部で最大 O(n) を使う）

2 回目（3 重ループの総当たり）:

- 時間: **O(n³ · t)**（t は見つかった組の数）— 3 つの組を全部試すのが n³。
  組が見つかるたびに `not in triplets` を 6 回して、結果のリストを先頭から探す（1 回 O(t)）
- 空間: O(t) — 結果のリストだけ

手元では n = 400 で約 0.5 秒。n が 2 倍で約 8 倍になる O(n³) の形で、制約の上限 n = 3000 だと数分かかる計算になる。

3 つの組をすべて試すと O(n³) なので、1 回目は 1 段減らしている。3Sum は O(n²) より速くする方法が知られていないので、これが目標の計算量。

## 学び・再利用できるパターン

### 1 つを固定すれば、残りは 167 Two Sum II

並べ替えたあと、1 つ目の数 `nums[i]` を固定すると、残りの問題は
「`nums[i]` より右から、足して `-nums[i]` になる 2 つを探す」になる。
これは [167. Two Sum II](../0167-two-sum-ii-input-array-is-sorted) そのもので、両端から寄せる 2 ポインタで O(n) で解ける。

**k 個の和は、1 つ固定して (k-1) 個の和に落とす**のが定番（4Sum なら 2 つ固定して 2 ポインタ）。

### 重複を出さない 2 か所

同じ値の組を 2 回返さないために、2 か所で重複を飛ばしている。

**1 つ目の数**: `previousFirstNumber` と同じ値なら、その `i` を飛ばす。
同じ値で固定しても、見つかる組は前と同じになるから。

**2 つ目・3 つ目の数**: 組が見つかったあと、`left` と `right` を 1 つずつ内側へ進め、
`nums[left - 1] == nums[left] and nums[right + 1] == nums[right]` の間は両方を進め続けている。

この `and`（両方が前と同じ値の間だけ進める）で正しい。
同じ組がもう一度見つかるのは、**左も右も前と同じ値**のときだけだから。
片方だけ値が変わっていれば、和が 0 からずれるので、普通の「小さければ左、大きければ右」で自然に進んでいく。
ランダムな 500 通りで総当たりと比べて、重複も漏れもないことを確かめた（`test_random_against_brute_force`）。

よく見る書き方は、左だけを `while left < right and nums[left] == nums[left - 1]: left += 1` で飛ばす形。
こちらも正しく、考えることが 1 つで済む。

### 細かい点

- ループの先頭の `print(f"i, nums[i] = …")` がコメントアウトされずに残っている。LeetCode では標準出力も時間に効く
- 並べ替えてあるので、`nums[i] > 0` になったら残りの 3 つはすべて正で、和が 0 になることはない。そこで `break` できる
- 最後のコメント「if there are duplicates in result array, remove them」は、実際には何もしていない。
  途中で重複を飛ばす形にしたので、最後に取り除く処理が要らなくなった名残

### 2 回目（9/6）: 総当たりに戻って TLE

1 回目（6/11）は「並べ替えて 1 つ固定 → 167 と同じ 2 ポインタ」で O(n²) だったが、
2 回目はその方法を思い出せず、3 重ループで全部の組を試す形になった。答えは正しい（テストはすべて通る）が、O(n³) で TLE。

| | 1 回目 | 2 回目 |
| --- | --- | --- |
| 方法 | 並べ替え + 1 つ固定 + 2 ポインタ | 3 重ループの総当たり |
| 重複の除き方 | 並べ替えてあるので、前と同じ値を飛ばす | 6 通りの並びをすべて結果リストから探す |
| 時間 | O(n²) | O(n³ · t) |
| 結果 | - | TLE |

**今回は 1 回目のほうが良かった。** 2 回目の重複チェックの苦労（6 通りの並びを全部書く）は、
**並べ替えれば一気に消える**。並べ替えたあとなら、組は必ず小さい順に `[nums[i], nums[j], nums[k]]` で作られるので、
同じ組は同じ並びになり、6 通りを考える必要がなくなる。
並べ替えは重複を扱いやすくするための準備でもあり、さらに 2 ポインタを使えるようにする準備でもある。

総当たりのままでも、重複チェックだけは軽くできる:
並べ替えた組を `tuple` にして `set` に入れれば、`not in` が O(1) になる（それでも O(n³) なので TLE は変わらない）。
