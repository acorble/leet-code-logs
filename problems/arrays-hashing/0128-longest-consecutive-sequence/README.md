## 問題の要約

整数の配列から、**連続した整数**（例: 1, 2, 3, 4）が最長で何個並べられるかを返す。配列の中での並び順は問わない。
**O(n) で解くこと**が条件（並べ替えると O(n log n) になるので使えない）。

## 計算量

n は配列の長さ、m は値の種類数。

- 時間: **O(m²)**（最悪 O(n²)）— 外側の `while` は「連続した並び」の本数だけ回り、
  そのたびに `Collections.min(set)` が set 全体を見て最小値を探す（O(m)）。
  値がすべて離れていると、並びが m 本できるので m × m になる。
  連続をたどる内側の `while` は、合計しても各値を 1 回ずつしか見ないので O(m) で済んでいる
- 空間: **O(m)** — HashSet

手元で、値がすべて離れている入力を Java のまま動かした結果:

| n | 時間 |
| --- | --- |
| 10⁴ | 約 0.3 秒 |
| 5 × 10⁴ | 約 11 秒 |
| 10⁵ | 約 40 秒 |

n が 2 倍になると時間が約 4 倍になっていて、O(n²) の形になっている。制約は n ≤ 10⁵ なので TLE になる。

## 学び・再利用できるパターン

### TLE の原因は `Collections.min(set)`

考え方の大部分はすでに正しい。

- HashSet に入れて `contains` で「次の数があるか」を O(1) で調べる
- たどった数は `remove` して、二度と数えない

遅いのは 1 か所だけで、**並びを 1 本たどり終わるたびに、set 全体から最小値を探し直している**ところ。
`HashSet` は中身を順番に並べて持っていないので、最小値を知るには全部を見るしかない（O(m)）。

「最小値から数え始める」のは、並びを途中から数えてしまわないようにするためだった。
O(n) にするには、**最小値を探さずに**「この数は並びの先頭か」を見分ける方法を考える
（次回やること。答えはここには書かないでおく）。

### `remove` しながらたどるのは良い工夫

たどった数を set から消しているので、同じ並びを 2 回数えることがない。
内側の `while` が全体で O(m) に収まっているのはこのおかげ。

### 細かい点（Java）

- `while (true) { if (…) { … } else { …; break; } }` は、
  `while (set.contains(nextTarget)) { … }` にして、ループの後で `maxLength` を更新すると短くなる
- `if (lengthCount > maxLength) maxLength = lengthCount;` は `maxLength = Math.max(maxLength, lengthCount);` と書ける
