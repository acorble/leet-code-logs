## 問題の要約

二分探索木の中で **k 番目に小さい値**を返す（k は 1 始まり）。

## 計算量

- 時間: **O(n log n)** — 全ノードを集めてから `sort()` している
- 空間: O(n) — 全値を配列に持つ

BST の性質を使えば **O(n)**、さらに途中で打ち切れば **O(h + k)** で解ける（→ 学びの節）。

## 学び・再利用できるパターン

- 「全部集めてソートして k 番目」は、**どんな木でも動く汎用の力技**。
  正しさを確保するには十分だが、BST であることを 1 ミリも使っていない
  （[235](../0235-lowest-common-ancestor-of-a-binary-search-tree) の 1 回目と同じ構図）

### BST の中順走査は、ソート済みの列そのもの

BST を **左 → 自分 → 右** の順（中順、in-order）で辿ると、
値が**小さい順に**出てくる。これは BST の定義から直接導かれる性質。

```
    5
   / \          中順: 1, 2, 3, 4, 5, 6
  3   6
 / \
2   4
/
1
```

- 今の解答は **前順**（自分 → 左 → 右）で集めているので順番がばらばらになり、
  あとで `sort()` が要る。**中順に変えるだけで sort が消えて O(n)** になる
- さらに、中順で k 個目を見つけた時点で**打ち切れば** O(h + k)。
  木の右半分を一切見ずに済む場合がある

→ 2 回目は「走査の順番を変えるだけで sort が要らなくなるか」から考える。
[98](../0098-validate-binary-search-tree) のテストで使った
「中順走査が単調増加なら BST」という判定も、同じ性質に基づいている。

### `nonlocal vals` は不要

```python
nonlocal vals
vals.append(node.val)
```

`nonlocal` が要るのは**変数に代入し直す**とき（`cnt += 1` や `vals = [...]`）。
`append` はリストの中身を変えるだけで、`vals` という名前を付け替えないので、
外側の変数をそのまま使える。[1448](../1448-count-good-nodes-in-binary-tree) では
`cnt += 1` だったので必要だったが、今回は無くても動く。

| 操作 | `nonlocal` |
| --- | --- |
| `cnt += 1`（数値を更新） | **要る** |
| `vals = sorted(vals)`（付け替え） | **要る** |
| `vals.append(x)`（中身を変える） | 要らない |
