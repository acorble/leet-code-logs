## 問題の要約

英数字だけを見て、大文字小文字を区別せずに回文かどうかを判定する。
記号や空白は無視する。英数字が 1 つも無い場合は回文とみなす。

## 計算量

- 時間: **O(n)** — 内側の while も含め、各文字を高々 1 回しか見ない
- 空間: **O(1)** — 文字列を作り直さず、添字だけで処理する

**これが最適**。`[c for c in s if c.isalnum()]` と作り直す書き方は簡潔だが、
O(n) の追加メモリを使う。

## 学び・再利用できるパターン

- **両端から中央へ寄せる 2 ポインタ**。回文判定の基本形。
  スライディングウィンドウ（片側から伸ばして片側を詰める）とは向きが違い、
  **左右から同時に内側へ**進む
- **飛ばす処理を内側の while に切り出す**。「見るべき文字まで進める」を
  外側のループと分けることで、比較のロジックが 1 行で済んでいる
- 内側の while が入れ子になっていても、`left` は増えるだけ・`right` は減るだけなので、
  **全体では各文字を 1 回しか見ない**。見た目の入れ子と計算量は一致しない
- 内側のループにも `left < right` の条件を入れているのが重要。
  これが無いと、英数字が無い文字列で添字が範囲外へ飛ぶ

### 文字列を作り直さないのが効いている

```python
cleaned = [c.lower() for c in s if c.isalnum()]   # 簡潔だが O(n) メモリ
return cleaned == cleaned[::-1]
```

こちらのほうが短く書けるが、**元の文字列と同じ大きさの配列を作る**。
この解答は添字だけで処理していて追加メモリが要らない。
「作り直す」か「その場で見る」かの分かれ道は
[206](../../linked-list/0206-reverse-linked-list) の 1 回目 → 2 回目と同じ構図。

正しさはランダム 2,500 パターン（回文になりやすい入力を含む）で確認済み。
