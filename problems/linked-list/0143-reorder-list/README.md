## 問題の要約

連結リスト `L0 → L1 → ... → Ln` を
`L0 → Ln → L1 → Ln-1 → L2 → ...` の順に**その場で**並べ替える。
= 前から 1 つ、後ろから 1 つ、を交互に繋ぎ直す。返り値は無し。

## 計算量

- 時間: O(n) — 1 周して配列に写し、もう 1 周で繋ぎ直す
- 空間: **O(n)** — 全ノードへの参照を配列に持つ

空間 O(1) で解く方法がある（→ 学びの節）。Beats 15.27% はこの差。

## 学び・再利用できるパターン

- **連結リストを配列に写すと、添字で自由に飛べる**ようになる。
  連結リストは「前から順にしか辿れない」のが制約なので、
  それを外すために配列に写すのは有力な発想。実装も追いやすい
- ただし O(n) の追加メモリを使う。連結リストの問題は
  **O(1) 空間でやることが期待されている**ことが多い（この問題もそう）

### O(1) 空間で解く定石（次に試すこと）

連結リストの 3 大操作を組み合わせると、追加メモリなしで解ける。

1. **中点を見つける**（slow / fast ポインタ。fast が 2 歩進む間に slow が 1 歩）
2. **後半を反転する**（prev / curr を持って `next` を張り替えていく）
3. **前半と後半を交互に繋ぐ**

この 1〜3 はそれぞれ 876. Middle of the Linked List / 206. Reverse Linked List /
21. Merge Two Sorted Lists という独立した問題になっている。
**小さい問題の組み合わせ**という点は、木の
[572](../../trees/0572-subtree-of-another-tree)（= 100 + 探索）と同じ構造。

### 添字の対応

配列に写したあとの繋ぎ方は `i` と `e - i` のペア。

```
[0] [1] [2] [3] [4] [5]        e = 5
 └───────────────┘  i=0 ⇔ e-0=5
     └───────┘      i=1 ⇔ e-1=4
         └───┘      i=2 ⇔ e-2=3
```

`while i < e - i` で「まだ交差していない間」だけ回る。
`(e - i) - i > 1` は「ペアの間にまだノードが残っているか」の判定で、
残っていなければ最後尾なので `next = None` のままにする。
