## レビュー: 面接の観点

### 良かった点

- **最初に問題を声に出して言い直した。** "Let me repeat the problem statement out loud first" から入り、"I need to invert the two children of each node for the entire binary tree" と自分の言葉にしている。面接の入り方として理想的。
- **コードを書く前に明確化の質問をした。** 根が None になりうるか（"Can the binary tree be just None?"）、木が平衡とは限らないか、子が片方だけのノードがあるか、を確認し、"I think there are three cases" とケースを並べている。
- **書く前に方針と計算量を言った。** DFS と BFS の 2 つがあると示し、DFS（再帰）を選んで時間 O(N) を先に宣言している。
- **ベースケースを理由付きで導いた。** "If we have None as a root here, these two lines are gonna be error. So the base case should be checking if the root is None or not." 再帰を書いてから「このままだと None で落ちる」と気づいてベースケースを足す流れを、声に出して見せられている。面接官には思考の過程が伝わる。
- **書き終えたら自分から質問を促した。** "Do you have any comments or questions?"
- **空間計算量の指摘から立て直した。** 偏った木（一直線）なら深さ N、平衡な木なら高さぶん、と 2 つの場合を対比し、例の木を使って O(h) にたどり着いている。

### 改善点

1. **空間計算量を最初から正確に言う（最優先）。**
   計画の段階では "Also, O(N), I think. Because we use recursion"、評価の段階では
   "we use some constant space ... So that I think that time complexity is going to be also O(1). Uh, no, no, O(N). If I'm not wrong." と揺れた。
   README の計算量の表には 1 回目から **O(h)** と書いてあるので、知識はあったのに口に出すときに出てこなかった形。
   次のように一息で言えるように型を作っておくとよい:
   "Space is O(h), where h is the height of the tree, because of the recursion stack. That's O(log n) for a balanced tree and O(n) in the worst case, when the tree is skewed like a linked list."
2. **書き終えたあと、例でコードを追っていない。** "I think this can work correctly" で評価に進んでいる。
   最初に挙げた 3 つのケース（右の子だけ・左の子だけ・両方）と None を使って、1〜2 分でよいのでコードを追って見せると「動くと思う」が「動くことを確かめた」に変わる。
   例: "Let me walk through a small example: 2 with children 1 and 3. We invert the left subtree, which is just 1, ..."
3. **値の扱いについての質問で時間を使った。** "The value of each node doesn't matter, right?" から、面接官が「判定のために値を見る」と説明するやりとりが長く続き、聞き返しも挟まった。
   質問自体は悪くないが、"I assume the values don't affect the inversion. I'll just swap the children." のように**仮定を言い切って先へ進む**形にすると、短く済む。
4. **DFS を選んだ理由を一言添える。** "There are DFS and BFS approaches" と示したのは良いので、
   "I'll go with recursive DFS since it's the simplest to write. BFS with a queue would also work and avoids deep recursion." と比較を 1 文入れると、トレードオフを分かっている印象になる（README の 2 回目の BFS 版とつながる）。
5. **コードを口述するときの順番。** 再帰の 2 行 → ベースケース → 入れ替えの 1 行、と行き来したので、聞いている側はどの行の話か追いにくい。
   "First, the base case. Then, the recursive calls on the left and right children. Finally, I swap them and return the root." と**最初に全体の骨組みを言ってから**各行を書くと伝わりやすい。
