2 pointersで解いてみた。dummy nodeを入れたやり方が少し慣れないがやり方は掴めた気がする。ただdummyを入れたおかげで、先頭ノードを消すというedge caseの場合だけ場合分けする必要がなくなった。

## 学び・再利用できるパターン

<!-- 次に似た問題が出たときに思い出したいこと -->

### 「後ろから n 番目」は「前から L − n 番目」

- 長さ L が分かれば、後ろから n 番目は前から（0 始まりで）**L − n 番目**。
  消すには、1 つ前（L − n − 1）の `next` を、1 つ後ろ（L − n + 1）につなぎ替える
- 長さは最後まで行かないと分からないので、今回は 1 周しながら全ノードを番号付きで覚えた。
  番号から直接ノードを引けるので、2 周目が要らない
- `nodes[index] = None` を足しておいたのが効いている。最後のノードを消す（n = 1）とき、
  「1 つ後ろ」が `nodes[L]` = None になり、末尾を特別扱いせずに済む
- キーが 0, 1, 2… の連番なので、dict ではなく list（`nodes.append(curr)`）でも同じことができる

```
[1, 2, 3, 4, 5], n = 2  →  L = 5, 消すのは前から 5 - 2 = 3 番目（値 4）
nodes[2].next = nodes[4]     # 3 → 5 につなぎ替える
```

### 場合分けの整理

- `index == 1` の分岐は、次の `n == index` の分岐に含まれている（長さ 1 なら n = 1 で、`head.next` は None）
- `if not head` も、制約（ノード数は 1 以上）の上では通らない
- 本当に特別扱いが要るのは**先頭を消す場合（n == L）だけ**。先頭には「1 つ前のノード」がないため。
  先頭の前にダミーのノードを 1 つ置くと、先頭も「1 つ前のつなぎ替え」で消せるようになり、この場合分けもなくなる。
  連結リストで先頭が変わりうる問題で広く使う形

### 定番の解き方: 2 つのポインタを n 個ずらす

- 先に fast を n 個進めてから、fast と slow を同時に 1 個ずつ進める。
  fast が末尾に着いたとき、slow は**消すノードの 1 つ前**にいる（2 つの間隔が常に n に保たれるため）
- 1 周で済み、追加の空間は O(1)。今回の解き方も 1 周だが、全ノードを覚えるぶん空間が O(L) になる。
  違いは「長さを数えて番号で引く」か「間隔を保って位置を合わせる」か
- 2 つのポインタの位置関係で目的の場所を見つける点は、[141](../0141-linked-list-cycle) の fast / slow と同じ仲間

### 2 回目で変わったこと

提出した直後に、自分で場合分けを 1 つ減らした（1 回目の「場合分けの整理」で挙げた 1 点目）。

- `index == 1` の分岐を消し、`if n == index` / `else` の 2 つだけになった。入れ子もなくなった
- 長さ 1 のリストは `n == index` の側で `head.next`（None）を返すので、答えは変わらない
- 残っている特別扱いは「先頭を消す」場合だけ。これはダミーのノードで消せる（次回やること）
- `if not head` は残した。関数定義が `ListNode | None` なので念のため、という判断。
  LeetCode の `Optional` はリスト・木の問題でほぼ機械的に付くもので、入力の範囲を決めるのは制約のほう。
  ただしこのコードでは、None が来るとループが回らず `nodes[-n - 1]` で KeyError になるので、
  チェックは実際に落ちる箇所を守っている。面接では "The constraints say there's at least one node,
  but the signature allows None, so I'll add a guard just in case." と理由を添えれば、どちらでもよい

### 3 回目で変わったこと

翌日に、次回やることの 2 つ（2 つのポインタ・ダミー）を両方入れて解き直した。
dict も番号の計算も場合分けも消え、本体は「ずらす → 同時に進める → つなぎ替える」の 3 段だけになった。

```
dummy → 1 → 2 → 3 → 4 → 5,  n = 2
fast を dummy から n + 1 = 3 歩進める       → fast = 3
slow = dummy から同時に 1 歩ずつ進める       → (1, 4) → (2, 5) → (3, None)
fast が None になった時点で slow = 3        → 3.next = 5 にして 4 を消す
```

- **n + 1 個ずらす理由**: 止めたいのは消すノード自身ではなく、その **1 つ前**（つなぎ替えるのは前のノードの `next` だから）。
  fast は末尾の「次」の None まで進むので、間隔を n + 1 にすると、そのとき slow はちょうど消すノードの 1 つ前にいる
- **slow をダミーから出発させる理由**: 先頭を消す場合（n == L）、fast は n + 1 歩で None に着き、ループは 1 回も回らない。
  slow はダミーに止まったままで、`dummy.next = head.next` で先頭が消える。1・2 回目で必要だった先頭の特別扱いが、ここで消えている
- 最初の `curr` はそのまま fast として使っている。`fast = dummy` から直接 n + 1 歩進めれば、変数が 1 つ減る
- `if not head` は消えた。head が None だと `curr.next` で落ちるが、制約（ノード数は 1 以上）の上では来ない
- 最初は fast を **head** から n + 1 歩進めようとして落ちた（考えたこと 3 回目）。
  head から数えると、n == L（先頭を消す）のとき L 歩目で None に着いたあと、さらに `None.next` を取ろうとして AttributeError になる。
  **ダミーから数えると最大でも L + 1 歩で、ちょうど None に着いて止まる**。ダミーは「1 つ前」を作るだけでなく、
  歩数の数え方をそろえる役目もしている
