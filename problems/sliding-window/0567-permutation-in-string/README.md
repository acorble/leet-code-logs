## 問題の要約

s1 の並べ替えのどれかが、s2 の**連続した部分文字列**として現れるかを判定する。
= s2 のどこかに、**s1 と同じ文字を同じ個数だけ含む窓**があるか。

## 計算量

- 時間: O(len(s2) × 文字種) — 1 文字進めるたびに `s1map == s2map` で dict 全体を比較する
- 空間: O(文字種)

（この解答には `print` が生きているので、実行時間はさらに増える）

## 学び・再利用できるパターン

- **2 つの頻度 dict を比べる**。欲しい形（s1）と今の窓（s2 の一部）を
  それぞれ dict にして、一致したら成立。
  [424](../0424-longest-repeating-character-replacement) と同じ「頻度 dict の窓」だが、
  424 は**窓の中の統計**を見ていたのに対し、こちらは**外部の目標と照合**している
- **s1 に無い文字が来たら窓を丸ごと捨てる**（`l = r + 1`, `s2map = {}`）のが効いている。
  その文字をまたぐ窓は絶対に成立しないので、縮めるのではなく捨てるのが正しい
- 同じ文字が多すぎるときは `while` で左を詰める。
  **「捨てる」と「縮める」を条件によって使い分けている**のがこの解答の特徴

正しさは総当たり 42,588 通り（s1 は長さ 1〜3、s2 は長さ 1〜6）で確認済み。

### dict の丸ごと比較が重い

```python
if s1map == s2map:      # 文字種のぶんだけ毎回比較する
```

1 文字進めるたびに dict 全体を比べているので、O(文字種) がループの中に入っている。

定石は **「一致している文字種の数」を 1 つの整数で持つ**こと。
ある文字の個数が目標とちょうど一致した瞬間に +1、外れた瞬間に −1 する。
その整数が文字種の数と等しくなったら成立、と **O(1) で判定**できる。

### 窓の作り方について

この解答は窓の長さを固定していないが、
**s1 の長さで固定した窓をずらす**書き方もある（右を 1 進めたら左も 1 進める）。
その場合「多すぎるときに縮める」処理が不要になり、
窓の長さが常に `len(s1)` なので比較も単純になる。

### 細かい点

`print(f"l = {l}, r = {r}")` が生きている。s2 の 1 文字ごとに出力されるので、
長い入力では実行時間の大半がこの出力になる
（[3](../0003-longest-substring-without-repeating-characters) で
print を消したら Beats が 19.65% → 70.81% に上がったのと同じ話）。
