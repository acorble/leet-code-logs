## 問題の要約

木を右から見たときに見える値を、上の層から順に返す。
= **各層でいちばん右にあるノードの値**を集める。

### 2 回目
久しぶりにLeetCodeやるので復習として解いた。結構感覚を忘れていてどう解いていたか忘れていた。
1回目の回答を見て思い出しながら同じようにdequeを使ったBFSで解いた。
1回目から改善した点：
- Noneチェックを最初に行うようにした。dequeよりも先に行うことで早期リターンが可能。
- for文でiは別に使ってないので `for i in range(len(q))`ではなく `for _ in range(len(q))`でいい。
学び：
- root=Noneだった場合dequeにNoneが入るのでNoneのleftやrightをその後見ることになりいきなりエラーで落ちる。なのでBFSでは先にNoneチェックするのが定番
- BFSで一気に全ノードを操作せず層ごとに何かをしたい場合、 `while q:`の中で `for _ in range(len(q))`を書くように、while文の中でfor文回して全ノード回らないようにする。

## 計算量

- 時間: O(n) — 各ノードを 1 回ずつ訪れる
- 空間: O(w) — queue。w = 最大幅。最悪 O(n)

## 学び・再利用できるパターン

- **[102. Level Order](../0102-binary-tree-level-order-traversal) の型がそのまま効く**。
  `len(q)` で層を区切り、その回数だけ取り出す。違いは
  「層の値を全部集める」か「最後の 1 つだけ残す」かだけ
- 層の値を溜めるリストすら要らない。ループ変数 `node` は最後に取り出したノードを
  指したまま残るので、ループを抜けた直後に `node.val` を見れば
  **その層のいちばん右**が取れる
- 「右から見える」= 「各層の最右」という**言い換えが本質**。
  これに気づけば、木を右から眺める必要はなく、いつもの層ごとの BFS になる
- 右の部分木が浅いときは、下の層で左側のノードが「見える」。
  `root.right` だけを辿る解法では間違える（テストの
  `test_left_subtree_is_deeper` がそのケース）

### None を queue に入れるか（模範解答との違い）

模範解答は `q.append(node.left)` と **無条件に入れて、取り出すときに None を判定**していた。
この解答は逆に **入れる前に判定**している。どちらも正しく、ガードの置き場所が違うだけ。

```
この解答:  if not root: return []        ← 早期 return
          if node.left: q.append(...)   ← 入れる前にガード
          ret.append(node.val)          ← 無条件に足せる

模範解答:  （早期 return なし）
          q.append(node.left)           ← 無条件に入れる
          if rightSide: res.append(...) ← 取り出す側でガード
```

| | 入れる前に判定（この解答） | 取り出してから判定（模範解答） |
| --- | --- | --- |
| queue に入る数 | 実ノード数 n | 最大 2n |
| `root=None` | 早期 return が必要 | 不要。自然に `[]` が返る |
| 空レベル | 不要 | 末尾のガードが必要 |

**片方を消すともう片方が要る**ので、ガードの総数は変わらない。計算量もどちらも O(n)。
queue が小さいぶんこの解答のほうがわずかに軽く、模範解答は特殊ケースの分岐が無いぶん対称。

同じ判断は [102](../0102-binary-tree-level-order-traversal) でも出ていて、
そちらは 1 回目が「入れる前」、2 回目が「取り出してから」だった。
**BFS を書くときは毎回この選択がある**と意識しておくと、迷わず決められる。

### 2 回目で変わったこと

アルゴリズムは 1 回目と同じ（層ごとの BFS で最後に取り出したノードを拾う）。
ただし約 5 週間ぶりで解き方を忘れており、**1 回目の解答を見ながら**書いている。
「`len(q)` で層を区切る」型はまだ自力で引き出せる状態ではないので、
次は何も見ずに書けるかを確かめたい。違いは書き方だけ:

- **早期 return を先頭に移した**。`root` が None なら queue を作る前に抜ける。
  「前提を確認 → 準備 → 本処理」の順になり、上から読んで自然
- **ループ変数を `_` にした**。`i` は使っていなかったので、
  「回数だけが欲しい」という意図がコードに出る
- **型ヒントを `TreeNode | None` / `list[int]` に**。Python 3.10 以降の書き方で、
  `typing` の import が要らなくなった
- コメントが `# append to ret here`（何をするか）から
  `# ここでのnodeは層ごとの右端になる`（なぜそれで正しいか）に変わった。
  後者のほうが読み手の役に立つ

1 回目の考察で挙げていた **DFS 版はまだ書いていない**。
右の子から先に潜り、各深さで最初に訪れたノードを記録する
（`len(ret) == depth` なら初訪問）形で、計算量は同じ O(n)、空間は O(h)。
