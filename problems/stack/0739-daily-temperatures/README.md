## 問題の要約

日ごとの気温の配列が与えられる。各日について「自分より**暖かい日**が来るまで何日待つか」を返す。
そういう日が来なければ 0。

### 2 回目

## 計算量

2 回目（単調 Stack）:

- 時間: **O(n)** — `while` が二重ループに見えるが、各日は Stack に 1 回積まれて最大 1 回取り出されるだけなので、
  push と pop は全体でそれぞれ n 回以下
- 空間: O(n) — 気温が下がり続ける入力では、全部の日が Stack に積まれたまま残る

1 回目（総当たり）:

- 時間: **O(n²)** — 各日 i について、それより後ろの日を最悪すべて見る
  （気温が下がり続ける入力では内側のループが一度も `break` しない）
- 空間: O(1)（出力の `ans` を除く）

制約は n ≤ 10⁵ なので、n² = 10¹⁰ 回になり TLE になる。
n = 10⁵ を通すには O(n) か O(n log n) が必要。

## 学び・再利用できるパターン

### 制約から必要な計算量を逆算する

| n の上限 | 通る目安 |
| --- | --- |
| 〜10³ | O(n²) でも通る |
| 〜10⁵ | O(n log n) か O(n) が必要 |

書き始める前に制約を見て「二重ループでは間に合わない」と分かれば、
総当たりを書いたあとで別の方法を探す時間を節約できる。

### 総当たりで何を無駄にしているか

今の解答は、各日 i ごとに右側を**毎回最初から**見直している。
後ろの日を見るときに「前の日たちのうち、まだ答えが決まっていないもの」をどこかに覚えておけないか、
と考えるのが次の一歩になる（Stack を使う解法はここから出てくる。答えは書かないでおく）。

### 「内側のループで見つからなかったら」を書くには `for ... else`

`len(ans) - 1 != i` で「`break` しなかったか」を判定しているが、
Python には `break` しなかったときだけ実行される `else` 節がある。

```python
for j in range(i + 1, len(temperatures)):
    if temp < temperatures[j]:
        ans.append(j - i)
        break
else:  # break しなかった（暖かい日が見つからなかった）ときだけ実行
    ans.append(0)
```

もう一つの定番は、`ans = [0] * len(temperatures)` で**先に 0 で埋めておき**、
見つかったときだけ `ans[i] = j - i` で上書きする方法。
「見つからない場合の値」が決まっている問題ではこちらが簡単で、判定そのものが要らなくなる。

### 細かい点

- `print` が 2 つ残っている。LeetCode では標準出力も時間に効くので、提出前には消す
- `print(range(i + 1, len(temperatures) - 1))` の `- 1` は、デバッグ中に直した名残
  （実際のループのほうは `len(temperatures)` に直っていて正しい）

### 1 回目 → 2 回目: 総当たりから単調 Stack へ

1 回目は各日から右を毎回見直していた（O(n²)）。2 回目は左から 1 回だけ見て、
「まだ答えが決まっていない日」を Stack に積んでおき、より暖かい日が来たときにまとめて答えを決める（O(n)）。
`print` も残っていない。

Stack を使える理由は、**待っている日は下から上へ温度が下がっていく順に並ぶ**こと。

```
temperatures: 73 74 75 71 69 72 76 73
日 4 のあと:   Stack = [75(日2), 71(日3), 69(日4)]   ← 下がっていく
日 5 (72):     69 < 72 → 日4 の答え 1、71 < 72 → 日3 の答え 2、75 ≥ 72 → 止める
               Stack = [75(日2), 72(日5)]
```

新しい日は Stack の上（最近の日 = いちばん低い日）から比べ、暖かくなければそこで止めてよい。
それより下はもっと高いので、確かめても答えは決まらない。これが「後入れ先出し」が合う理由。

このように、中身が常に単調（ずっと下がる / ずっと上がる）になるよう保つ Stack を**単調 Stack**と呼ぶ。
「次に来る、自分より大きい（小さい）もの」を探す問題の定番。
[853. Car Fleet](../0853-car-fleet) の「先頭から見て、これまでの最大より遅ければ新しい集団」も同じ発想。
未着手の [84. Largest Rectangle in Histogram](https://leetcode.com/problems/largest-rectangle-in-histogram/) も単調 Stack で解く。

### `while` の中に `while` に見えても O(n) のことがある

`for` の中に `while` があると O(n²) に見えるが、`while` で pop できる回数は**全体で** push した回数まで。
1 つの日ごとではなく、全体で何回起きるかを数えると O(n) と分かる（ならし計算量）。

### 細かい点（2 回目）

- 先に `ans = [0] * len(temperatures)` で埋めているので、暖かい日が来ない日の処理を書かずに済んでいる
  （1 回目の学びで挙げた形）
- 取り出した組を `minimum` と名付けているが、中身は `(温度, 添え字)`。
  `t2, j = stack.pop()` のように受け取ると `ans[j] = i - j` と読みやすくなる
