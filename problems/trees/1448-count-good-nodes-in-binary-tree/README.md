## 問題の要約

根からそのノードまでの経路上に、自分より大きい値が 1 つも無いノードを good と呼ぶ。
good なノードの個数を数える。根は必ず good。同じ値は good を妨げない。

### 1 回目

<!-- 最初に思いついた方針、詰まった点、気づき -->
- 一応解けた。
- nonlocalを初めて使った。nonlocalがないとinner function内で新たに定義する変数だと解釈してしまうらしい。nonlocalを入れることでこれは外側の変数だと認識させ、cntをインクリメントすることができるようになった。
- Beats5%で反省の余地あり。多分「Good nodeかどうか」の判定を0(h)？でやってしまっているため遅い。


## 計算量

- 時間: **O(n × h)** — 各ノードで経路 `path` を毎回すべて走査している。
  偏った木では最悪 O(n^2)
- 空間: O(h) — 再帰スタックと `path`

O(n) で解ける（→ 学びの節）。Beats 5.16% はこの差。

## 学び・再利用できるパターン

- **経路を持ちながら潜る DFS**。`path.append` → 再帰 → `path.pop` の 3 点セット。
  pop を忘れると兄弟の枝に前の経路が漏れる（テストの
  `test_siblings_are_independent` がその検出用）
- 判定は「**直前の親**」ではなく「**経路上のすべての祖先**」と比べる必要がある。
  親より大きくても、もっと上の祖先より小さければ good ではない
  （テストの `test_max_is_not_the_parent`）
- 「自分より大きい値が無い」なので、**祖先と同じ値なら good**。`<` と `<=` の区別が効く

### 持ち歩く情報を減らせないか

経路を丸ごと持って毎回全部と比べているが、判定に必要なのは
「**経路上の最大値**」1 つだけ。最大値さえ分かれば、それ以外の値は結果に影響しない。

- 配列の代わりに数値 1 つを再帰の引数として渡せば、
  各ノードの判定が **O(1)** になり、全体で **O(n)**
- `path.append` / `pop` も不要になり、`nonlocal` も避けられる
  （子の結果を足し算して返す形にできる）

→ 2 回目は「path のうち、本当に要る情報は何か」から考える。

### `nonlocal` について

内側の関数から外側の変数を書き換えるためのキーワード。今回が初使用。

- 無いと `cnt += 1` が「新しいローカル変数 cnt を作る」と解釈され、
  `UnboundLocalError` になる（読むだけなら `nonlocal` は不要）
- 使わずに済ませる方法もある。**各ノードが「自分以下の部分木の good の個数」を
  返す**形にすれば、親が `1 + 左 + 右` と足し算するだけで済み、外側の変数が要らない。
  この形は [110. Balanced Binary Tree](../0110-balanced-binary-tree) や
  [235. LCA](../0235-lowest-common-ancestor-of-a-binary-search-tree) で
  既に書いている「下から情報を持ち上げる」型と同じ

| | 外側の変数に溜める（今回） | 返り値で持ち上げる |
| --- | --- | --- |
| 必要なもの | `nonlocal` | なし |
| 各ノードの返り値 | なし | その部分木の good の個数 |
| 110 で使った形 | — | ○ |
