## 問題の要約

1 本道の上で、各車の位置と速さが与えられる。後ろの車は前の車を追い越せず、追いついたら前の車の速さに合わせて一緒に走る（車団 = fleet）。ゴール `target` に到着する車団の数を返す。

### 1 回目

<!-- 最初に思いついた方針、詰まった点、気づき -->
左にある車でゴールまで到着する時間が短いものがあれば、必ずゴールまでに追いつかれるのでそれが一つのFleetになることは気づけた。
なのでゴールまで到着するまでの時間を並べて、ゴールから近い順に左に見ていって、時間が早い車までは全部1Fleetに含めるように数えればOKということは分かった。
が、与えられる車のposition, speedの要素順が位置順ではなくランダムなので位置順になるように並び替える必要があることまで気づけたが方法が思いつかず一旦submit。
あと回答をClaudeにレビューしてもらって気づいたが、時間の比較するときに整数に丸めないほうが良い。小数のまま比べればよかったのでもっとシンプルだった。

## 計算量

- 時間: O(n log n)（位置でのソートが支配的。その後の走査は O(n)）
- 空間: O(n)（ソートした組と到着時間のリスト）

## 学び・再利用できるパターン

<!-- 次に似た問題が出たときに思い出したいこと -->

- 「前が詰まると後ろが合わせる」系は、**先頭（ゴールに近い側）から順に見る**。そのために位置でソートする。
  入力の並び順がそのまま意味を持つとは限らない
- 先頭から見て「これまでの最大の到着時間」より遅ければ新しい集団、そうでなければ吸収される。
  集団の到着時間は先頭の車の時間で決まる（単調スタックで、積まれる値が単調増加になる形）
- 比較に使う値を丸めない。切り上げると本来区別すべき 1.2 と 1.5 が同じになる。
  浮動小数点が気になるなら `(target - p) * s2` と `(target - p2) * s` のような掛け算で比べる

- 2 回目: 複数の配列を同じ順番で並べ替えたいときは `sorted(zip(a, b))` で組にしてから並べる。
  タプルは先頭の要素から順に比べられるので、`a` の順に並び、`b` も一緒に動く。
  降順にしたければ `reverse=True`。昇順のまま後ろから `pop()` しても同じ（今回の解答はこちら）
- `sorted(x)` と `x.sort()` はどちらも Timsort で O(n log n)。`sorted` はイテラブルなら何でも受け取り、新しい list を返す（追加メモリ O(n)）。
  `.sort()` は list をその場で並べ替えて `None` を返す（`x = x.sort()` と書くと `x` が `None` になる）。
  `zip` は list ではないので `.sort()` は使えない。`list(zip(...))` にしてからなら使える
- `zip()` はイテレータを返す。呼んだ時点では何もしない（O(1)）。中身は読まれるときに 1 組ずつ作られ、全部読むと O(n)。
  1 回読み切ると空になるので、2 回使うなら `list(zip(...))` にしておく。
  計算量はソートの O(n log n) に吸収される
