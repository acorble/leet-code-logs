## 計算量

- 時間: **O(n)** — トークンを 1 回ずつ見て、push / pop はどれも O(1)
- 空間: **O(n)** — 数字が続く入力では、最大で約 n/2 個が Stack に積まれる

## 学び・再利用できるパターン

### 「直前のもの」と組み合わせて処理するなら Stack

逆ポーランド記法では、演算子が来たときに使うのは**直前に積まれた 2 つの数**。
「いちばん最後に入れたものから取り出す」ので Stack（後入れ先出し）がそのまま合う。

```
tokens:  2   1   +   3   *
stack:  [2] [2,1] [3] [3,3] [9]
```

同じ形の問題:
[20. Valid Parentheses](https://leetcode.com/problems/valid-parentheses/)（`)` が来たら直前の `(` と対応させる）、
[739](../0739-daily-temperatures)（新しい日が来たら、直前に待っていた日から確認する）。

### pop の順番に注意: 先に出てくるのは「右側」の数

`+` と `*` は順番を入れ替えても答えが同じなので `stack.pop() + stack.pop()` で済む。
`-` と `/` は順番が効くので、`a, b = stack.pop(), stack.pop()` で受けて `b - a` にしている。
**先に pop した `a` が右側の数**（後から積んだほう）になる。ここを逆にするのが典型的なバグ
（`test_subtraction_order` で確認している）。

### 0 方向への切り捨ては `int(b / a)`。`//` ではない

| 式 | 結果 | 丸め方 |
| --- | --- | --- |
| `-7 // 2` | -4 | 負の無限大方向（床関数） |
| `int(-7 / 2)` | **-3** | 0 方向（問題の指定） |

Python の `//` は負の数で答えがずれる。正の数だけのテストでは気づけないので、
負の数の割り算をテストに入れている（`test_negative_division_truncates_toward_zero`）。

### 演算子を dict にまとめる書き方

```python
import operator

ops = {
    "+": operator.add,
    "-": operator.sub,
    "*": operator.mul,
    "/": lambda b, a: int(b / a),
}
for c in tokens:
    if c in ops:
        a, b = stack.pop(), stack.pop()
        stack.append(ops[c](b, a))
    else:
        stack.append(int(c))
```

演算子が増えても分岐が増えない。どの演算子も pop の順番が同じになるので、
`-` と `/` だけ順番を気にする必要もなくなる。

### 細かい点

- `int(c)` は `"-11"` のような負の数も読める。演算子かどうかは `c == '-'` の完全一致で
  判定しているので、`"-11"` が引き算と間違われることはない
- 最後の `stack[0]` は、正しい式なら Stack に 1 つだけ残るので `stack.pop()` と同じ
