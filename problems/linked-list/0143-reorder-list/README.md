## 問題の要約

連結リスト `L0 → L1 → ... → Ln` を
`L0 → Ln → L1 → Ln-1 → L2 → ...` の順に**その場で**並べ替える。
= 前から 1 つ、後ろから 1 つ、を交互に繋ぎ直す。返り値は無し。

## 学び・再利用できるパターン

- **連結リストを配列に写すと、添字で自由に飛べる**ようになる。
  連結リストは「前から順にしか辿れない」のが制約なので、
  それを外すために配列に写すのは有力な発想。実装も追いやすい
- ただし O(n) の追加メモリを使う。連結リストの問題は
  **O(1) 空間でやることが期待されている**ことが多い（この問題もそう）
  → 5 日後の 2 回目で O(1) 空間に到達した（下記）

### O(1) 空間の定石（2 回目で到達）

連結リストの 3 大操作を順に適用すると、追加メモリなしで解ける。

| 手順 | やること | 単体の問題 |
| --- | --- | --- |
| 1 | **中点を見つける** — slow が 1 歩進む間に fast が 2 歩 | 876. Middle of the Linked List<br>（同じ道具を [141](../0141-linked-list-cycle) では循環検出に使う） |
| 2 | **後半を反転する** — prev / curr で `next` を張り替える | 206. Reverse Linked List |
| 3 | **前半と後半を交互に繋ぐ** | 21. Merge Two Sorted Lists |

3 つの独立した問題の組み合わせになっている。
**小さい問題が部品になる**という点は、木の
[572](../../trees/0572-subtree-of-another-tree)（= 100 + 探索）と同じ構造。

### 2 回目で変わったこと

- 配列に写すのをやめ、**ポインタの張り替えだけ**で完結させた → 空間 O(n) → **O(1)**
- 3 つの部品それぞれで、**一時変数に次のノードを退避してから繋ぎ替える**のが共通の型。
  連結リストは繋ぎ替えた瞬間に元の `next` を見失うので、先に確保しておく

  ```python
  tmp = headSecond.next      # 先に退避
  headSecond.next = prev     # 繋ぎ替え
  ```

  マージ部分の `headNext` / `prevNext` も同じ理由
- `slow.next = None` で**前半と後半を切り離す**のが要。
  切らないと後半を反転したときに循環ができる
- `fast = head.next` から始めている（`head` からではなく）。
  偶数長のときに slow が前half の末尾に来るようにするための半歩ずらし

### 添字の対応

配列に写したあとの繋ぎ方は `i` と `e - i` のペア。

```
[0] [1] [2] [3] [4] [5]        e = 5
 └───────────────┘  i=0 ⇔ e-0=5
     └───────┘      i=1 ⇔ e-1=4
         └───┘      i=2 ⇔ e-2=3
```

`while i < e - i` で「まだ交差していない間」だけ回る。
`(e - i) - i > 1` は「ペアの間にまだノードが残っているか」の判定で、
残っていなければ最後尾なので `next = None` のままにする。
