## 問題の要約

高さの配列 `height` から 2 本の線を選び、その間に溜められる水の量（**幅 × 低いほうの高さ**）の最大を返す。

## 計算量

- 時間: **O(n)** — 内側の `while` も含めて、`left` は増えるだけ・`right` は減るだけなので、合計で n 回以下しか動かない
- 空間: **O(1)**

全部の組を試すと O(n²)。

## 学び・再利用できるパターン

### 低いほうを動かす理由

両端から始めると、幅は最大。ここから内側へ動かすと、幅は必ず 1 減る。
水の量は「幅 × 低いほうの高さ」なので、増える可能性があるのは**低いほうの高さが上がるとき**だけ。

- **高いほうを動かす**と、低いほうの高さは変わらないか下がる。幅も減るので、水は**絶対に増えない**
- **低いほうを動かす**と、もっと高い線に出会えば増える可能性がある

だから、低いほうの線は「今の相手（いちばん遠い高い線）と組んだのが、その線にとっての最大」と分かり、候補から外せる。
[167](../0167-two-sum-ii-input-array-is-sorted) の「和が小さければ左を外せる」と同じく、**1 回の比較で片方を確実に外せる**形。

### 元より低い線を飛ばすのは正しい工夫

この解答は、低いほうを 1 つ動かすだけでなく、**元の高さより高い線が来るまで**まとめて進めている。
元より低い（か同じ）線は、幅も高さも元より小さいので、水が増えることはない。計算を省いても答えは変わらない。
ランダムな 500 通りで総当たりと比べて、正しいことを確かめた。

### もっと短い形

左右の処理がほぼ同じコードの繰り返しになっている。「低いほうを 1 つ動かす」を 1 本のループで書くとこうなる。

```python
left, right = 0, len(height) - 1
best = 0
while left < right:
    best = max(best, (right - left) * min(height[left], height[right]))
    if height[left] < height[right]:
        left += 1
    else:
        right -= 1
return best
```

最初の両端の計算もループの 1 回目に含まれるので、別に書く必要がなくなる。

### 細かい点

- 変数名 `max` は Python の組み込み関数 `max()` を上書きしてしまう。この関数の中では `max(a, b)` が使えなくなるので、`best` や `max_area` にする
- `if height[left] < height[right]: … else: …` で低いほうの高さを選ぶ部分は `min(height[left], height[right])` と書ける
- コメントの `poniter` は `pointer` のタイプミス
